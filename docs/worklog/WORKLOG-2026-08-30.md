## 발단 — 인사가 하루 한 번이고, 인사만 하는 법이 없었다

앱을 켜면 나오던 "오늘의 한마디"는 두 가지가 걸렸다.

1. **하루에 컴퓨터를 여러 번 켜도 첫 실행 때만 말한다.** 브리핑 캐시 키가 `(user_id, date)`라
   그날 두 번째 실행부터는 `get_today()` 히트로 조용히 끝났다.
2. **인사에 늘 훈수가 따라붙는다.** [D-022]가 인사를 브리핑 프롬프트 안에 넣어 뒀기 때문에
   "좋은 아침이에요" 뒤에 반드시 "지금 이걸 하세요"가 붙었다. 인사만 받고 싶은데 매번 할 일
   얘기를 듣는 셈이라 오히려 거슬렸다.

D-022 당시엔 한 덩어리가 옳았다 — 인사도 브리핑도 "그날 처음 켤 때 한 번"이라 주기가 같았다.
이번에 요구가 바뀌면서 **주기가 갈라진 것**이 이번 변경의 전부다.

## 결정 — 주기가 다른 두 가지로 쪼갠다

| | 인사 | 모닝 브리핑 |
|---|---|---|
| 트리거 | 앱 프로세스 시작 | 인사와 같되 아침 창 안일 때만 |
| 빈도 | 쿨다운 3시간 | 하루 한 번(기존 캐시 그대로) |
| 내용 | **인사만** | 오늘 짚을 것 하나 |
| 표시 | 채팅 말풍선 | 브리핑 카드 |

- **트레이에서 창을 여닫는 건 트리거가 아니다** — 프로세스가 살아 있으므로 호출 자체가 없다.
- 아침 창 기본 05:00~13:00, 설정 → 알림 탭의 "모닝 브리핑 시간"에서 조절. 창 밖에서 켠 날은
  인사만 하고 브리핑은 아예 만들지 않는다.
- 말투는 해요체 유지. "또 봐요" / "오늘 뭐 했어요?" / "며칠 만이네요" / "오랜만이에요, 잘 지냈어요?".

## 구현하며 정한 것들

- **"인사는 인사만"을 지키는 법**: 일정·할 일을 프롬프트에 **아예 싣지 않는다**. 실으면 LLM이
  반드시 짚는다(브리핑 프롬프트가 그 증거). 폴백 문구 풀도 같은 규칙이고, 테스트가
  `할 일`/`일정`/`마감` 문자열을 금지해 못 박는다.
- **"며칠 만"은 캘린더 일수로**. 경과 시간으로 재면 20시간이 같은 날일 수도 이틀 밤을 걸칠 수도
  있는데 사람이 체감하는 건 후자다. 기준선은 **마지막 인사와 마지막 사용자 발화 중 나중 것** —
  인사 시각만 보면 앱을 며칠 켜 둔 채 매일 대화한 사람이 재부팅할 때 "3일 만이네요"가 나온다.
- **마이그레이션 0건**. 쿨다운 기준선은 `settings`의 `greeting.last_greeted_at` 한 줄이고
  **allowlist에 넣지 않았다**(UI가 쿨다운을 리셋할 수 있으면 안 된다). 되돌리기는 코드 revert뿐.
- **인사 한 번의 보장은 Core에서**. 쿨다운 갱신을 조건부 upsert로 하고 `rows_affected()`로 승자를
  가린다. 그 위에 역할 분리를 얹었다 — 호출·TTS는 AvatarApp, 말풍선은 PanelApp.
  `useBriefingStore`의 `pendingAutoPlay`/`consumeAutoPlay`는 제거했다: 두 React 트리에 스토어
  인스턴스가 갈라져 있어 one-shot 플래그가 창마다 따로 존재하는 게 애초에 중복의 원인이었다.
- **인사는 LLM 컨텍스트에 최근 1건만**. 전부 빼면 "오늘 뭐 할 거예요?"에 답했을 때 모델이 자기
  질문을 못 보고, 전부 넣으면 `HISTORY_TURN_CAP`(40)이 인사로 도배된다.
- `TimeSlot::framing()` 삭제. 브리핑이 아침 전용이면 나머지 슬롯 분기는 죽은 코드다.
  `TimeSlot`/`label()` 자체는 인사가 계속 쓰므로 `greeting::pure`로 이관했다.
- `speakSequence`의 인사 phase를 `attentive` → `speaking`. attentive는 wake에 귀 기울이는
  자세지 먼저 말을 거는 자세가 아니다. wake의 "네, ○○님"([D-010])은 그대로.

## 미해결 / 후속
- **브리핑 텍스트는 지금도 `messages`에 저장되어 히스토리 복원 때 카드와 별개로 말풍선으로도
  보인다.** 이번 변경 이전부터의 동작이라 손대지 않았다. 거슬리면 `chat_history`에서
  `source='briefing'`을 거르는 3줄이면 된다.
- **쿨다운 3시간은 상수 하나**(`greeting::pure::COOLDOWN_HOURS`). 써 보고 안 맞으면 설정으로
  노출하는 건 allowlist 한 줄 + UI다.
- **배포 순서는 Core 먼저.** 구 Core + 신 렌더러면 `greeting.run`이 method-not-found로 던진다
  (부팅은 막히지 않는다 — `useStartupStore`가 `error`만 세우고 넘어간다).
