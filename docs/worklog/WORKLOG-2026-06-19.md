# 작업 기록 — 2026-06-19

## 패널 창 상단 드래그 영역이 최상단에 안 닿던 문제 수정

### 증상
패널(대화) 창을 옮길 때 창의 진짜 위쪽 끝이 아니라 살짝 아래를 잡아야만
드래그가 동작했다.

### 원인
패널 드래그는 `-webkit-app-region: drag`(헤더 엘리먼트)로 OS가 hit-test 한다.
그런데 `.panel-card`의 위쪽 1px `border`가 `box-sizing: border-box`에서 최상단
1px를 **레이아웃으로 차지**해, 드래그 영역인 `<header>`가 창 y=0이 아니라 1px
아래부터 시작했다. 여기에 Win11 frameless + transparent + 분수 DPI surface
라운딩(±1-2px, `windows.ts` 주석에 기록된 현상)이 더해져 최상단 몇 px가 드래그로
안 잡히는 죽은 영역이 됐다.

### 수정
`globals.css`의 `.panel-card` 위쪽 hairline을 `border: 1px` → Tailwind
`ring-1 ring-inset ring-white/[0.06]`(inset box-shadow 기반)로 교체. ring은
레이아웃 공간을 안 먹어 헤더가 창 최상단에 딱 붙고, 드래그 영역도 진짜 끝까지
닿는다. 시각적으로는 동일(흰색 6% 1px, `rounded-widget` 곡률·`shadow-2xl`과 정상
합성).

- 드래그 핸들을 헤더 단일 엘리먼트로 유지(오버레이 스트립/매직 넘버 없이 구조적으로 해결).
- 검증: renderer typecheck 통과, `npm run dev` 실수동 드래그 확인.

### 후속
- 없음. 네이티브 드래그 영역은 자동화 테스트가 불가해 수동 확인에 의존.

## 패널을 작업표시줄 창으로 + 불투명 전환 (브랜치 `feat/panel-taskbar-window`)

### 무엇을·왜
사용자 요청: **아바타는 순수 위젯(작업표시줄 미점유), 패널은 일반 창처럼 작업표시줄+
최소화/복원**. 진행 중 transparent 창 특유의 등장 깜빡임·둥근 모서리 아티팩트가 연달아
드러나, 패널을 **불투명(opaque) 창으로 전환**하는 게 근본 해법임을 확인하고 거기까지 진행.

### 변경 요약
- 아바타 `skipTaskbar:true`(위젯), 패널 작업표시줄 창화 + 헤더 **최소화(─)/닫기(✕)** 버튼.
  신설 IPC `window.minimize`(Main 자체 처리, core forward·zod 없음).
- 패널 `transparent:false`(`#121216`) + `roundedCorners`(Win11 네이티브) + `hasShadow`.
  → transparent 레이어드 윈도우의 first-show 흰 깜빡임 원천 차단(카카오톡/브라우저 원리).
- 여닫기는 `hide()`/`show()` 대신 **offscreen-park**: 둥근 opaque 창을 hide/show하면 모서리가
  한 프레임 각지게 깜빡여서. 닫기=park+`setSkipTaskbar(true)`, 열기=onscreen 이동, 최소화=네이티브.
- opacity 등장 애니메이션 제거(불투명 창에서 "검은 박스 한 프레임" 유발).
- 상단 드래그: ring(앞 섹션)에 더해 PanelApp 최상단 6px drag 스트립으로 보장.
- 관련: [D-019], [D-005](재채택). 현재 동작 정본 = `docs/UI/windowing.md`.

## UI 다듬기 — 글씨 크기·스크롤바·채팅 입력창

위 백로그 ①을 포함한 패널 가독성/완성도 다듬기 묶음.

- **글씨 크기 통일**(가독성): 설정·상단바의 `text-[10px]`/`[11px]`을 전부 12px↑로. 헤더 탭·섹션
  제목 14px(`text-sm`), 본문·라벨·버튼·인풋 12px(`text-xs`). **sub-12px 금지**를 `docs/UI/README.md`에
  타이포·밀도 규칙으로 명문화(백로그 ① 처리).
- **커스텀 스크롤바**: 기본 Chromium 스크롤바가 두껍고 밝아 위젯과 안 어울려, 8px 트랙/~4px thumb
  (흰색 12%, hover 24%)·투명 트랙으로 `globals.css`에 전역 적용.
- **채팅 입력창 재구성**: 입력창을 가로 꽉 채우고 min-h 64px(자동확장 160px)로 키움. 마이크(좌)·
  전송(우) 버튼을 입력창 **아래 행**에 양끝 정렬(밸런스). 입력창이 주변과 색이 비슷해 잘 안 보이던
  문제 → 배경 `bg-elevated/70` + 또렷한 보더로 구분.

검증: renderer typecheck 통과. 시각 변경이라 `npm run dev` 실사용 확인.
후속: 설정 화면 입력칸들도 채팅 입력창과 동일 스타일로 통일할지 여지(미정).
