## 채팅 목록 렌더를 텍스트 → 카드로 전환 (`269fac0`)

**의도**: "할 일 목록" 같은 조회 응답이 LLM이 받아쓴 마크다운 텍스트라 모양이 투박하고,
매 턴 목록을 토큰으로 다시 뱉으며, 값이 틀릴 여지도 있었다. Core가 이미 도구 결과 JSON을
쥐고 있는데 렌더러로 넘기지 않던 손실 경로를 없앴다.

**구조**: `ChatTurn.tool_results`(원본 JSON 그대로) → 클라이언트가 정규화·렌더.
데스크톱은 카드(`lib/chatCards.ts` + `components/chat/cards/`), 텔레그램은 평문 포맷터.
정본 문서 = `docs/UI/chat-cards.md`(신설, UI 인덱스 등록).

**같이 한 것**
- 표시 지침을 "나열" → "요약만"으로. 시스템 프롬프트의 "일정·할 일은 구조에 맞춰 더
  길어져도 됩니다"가 지침을 이기고 있어 그 규칙을 교체한 뒤에야 실제로 반영됐다.
- 쓰기 승인 직후 갱신 목록 카드(`fresh_list_after_write`) — 연속 작업의 **마지막 턴에만**.
  합성 카드는 history에 남길 수 없어(짝 없는 tool 메시지 = OpenAI 프로토콜 위반)
  스토어 `sessionCards`로 들고 재마운트 시 되붙인다.
- `WRITE_FOLLOWUP_HINT` — 한 턴 쓰기 1건 제한 탓에 "기한 지난 할 일 다 지워줘"가 첫 건에서
  끊기던 문제. 프롬프트 기반이라 100% 보장은 아니다([D-016]과 같은 결).
- 마크다운 홑 줄바꿈 렌더 수정, 답변 끝 문체 라벨(Hemingway) 차단, **말투 해요체 통일**
  (말투를 정하는 문구가 어디에도 없어 해요체/합쇼체/반말이 섞이고 있었다. 브리핑 프롬프트에도 적용).
- 기존에 깨져 있던 `present_decorate_target` 테스트 2건 복구(`list_todos`가 지침 대상이 된
  뒤 갱신 안 된 상태였음 — 이번 변경과 무관한 선재 실패).

## 할 일 수정 도구 신설 + 마감 정규화 (`7fb679c`)

**발단**: "제목에서 날짜 빼고 마감으로 넣어줘" 요청에 모델이 할 일 2건을 삭제만 하고
재생성하지 않아 **데이터가 사라졌다**. 원인은 도구 공백 — 일정에는 `update_event`가 있는데
할 일에는 수정 도구가 없어 삭제+재생성으로 우회했다.

- `update_todo` 신설(부분 수정, dispatch에서 기존 값 병합) + 확인 카드 + 텔레그램 라벨.
  `delete_todo` 설명에 "수정이면 삭제 금지" 경고.
- 마감 정규화를 **Core에 결정론적으로** 구현. 프롬프트로는 모델이 절반만 따랐다
  (`경포대마라톤`은 23:59로 정확, `졸업식(8.21)`은 제목에 날짜 남기고 00:00Z).
  규칙: 제목 끝 날짜 분리 / 자정 마감은 그 값 자신의 오프셋 기준으로 판정해 로컬 23:59 /
  명시된 시각은 보존. 채팅·할 일 탭 양쪽 적용, 단위 테스트 7건으로 고정.
