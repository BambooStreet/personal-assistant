## 앱 표시 이름을 MIYA로 변경 (`ec48daa`)

**의도**: 설치·실행 시 노출되는 이름이 `personal-assistant`(리포/패키지 식별자)로 뜨고 있어
제품명 **MIYA**로 통일했다.

**원인**: Electron `app.getName()`은 최상위 `productName` → `name` 순으로 읽는데 루트
`package.json`에는 `build.productName`만 있고 최상위 `productName`이 없어서 `name` 값이
그대로 노출됐다. 최상위 `productName: "MIYA"`를 추가해 해결.

같이 맞춘 곳: `build.productName`, `nsis.shortcutName`, 트레이 툴팁(`tray.ts`),
패널 창 `title`(`windows.ts`), 그리고 Vite 템플릿 잔재였던 `index.html`의
`Tauri + React + Typescript`.

**유지한 것**: `appId`(`dev.ohmyhong.personalassistant`). NSIS 설치 identity와 auto-update
연속성이 appId에 묶여 있어 바꾸면 기존 사용자에게 **중복 설치**로 보인다. `applyLegacyDataDir()`이
userData 경로를 이 문자열로 고정하고 있어 DB/설정도 그대로 유지된다.

**후속**: 다음 배포부터 설치 경로가 `...\Personal Assistant\` → `...\MIYA\`, 실행 파일도
`MIYA.exe`. appId가 같아 in-place 업그레이드지만 사용자가 수동으로 만든 바로가기는 깨질 수 있다.
다음 패키징 때 실제 업그레이드 경로 1회 확인 필요.

## 목표(goals) + 루틴 알림 (`feat/goals` → `f5c288c`, D-021)

**의도**: 아침 브리핑을 "오늘의 한마디"로 바꿔 놓고(`2dd809d`) 정작 프롬프트가 말하는 *"목표에
한 걸음"* 의 **목표가 DB에 없었다.** 마감 임박한 할 일을 목표인 척 짚고 있던 셈. 사용자가 장기
목표와 그 '왜'를 등록하면 스스로 정한 시각에 그 '왜'를 담은 알림을 받게 했다.

기능은 **3개로 의도적으로 잘랐다** — 목표(제목+왜 여러 개), 루틴(요일+시각, 목표당 여러 개),
알림(아침 브리핑 고정 줄 + 정한 시각 OS 알림). 진척률·스트릭·대시보드·마일스톤·주간 회고·
완료 추적·채팅 도구·텔레그램은 **안 만들었다**. 매일 오는 알림이 실제로 먹히는지부터 검증한다.
근거와 재도입 기준은 D-021.

**설계에서 갈린 지점** (자세히는 D-021)
- 루틴 발화를 `notifications::tick()`의 **형제 함수**로 뺐다. `tick()`은 DND면 함수 전체를
  early return 하는데 루틴은 사용자가 직접 정한 시각이라 DND를 통과해야 한다. 마스터 스위치
  (`notifications.enabled`)는 존중. 새 설정 키는 추가하지 않았다.
- 요일은 **비트마스크**(bit0=월, 매일=127). chrono `num_days_from_monday`와 일치해 변환이 없고
  SQL에서 오늘치만 걸러 온다. ⚠️ `DateField` 달력은 0=일이라 규약이 다름 — 테스트로 잠갔다.
- LLM 문구 실패 시 **폴백으로 반드시 발화**. D-018(이동 알림)의 degrade 원칙과 반대 방향인 게
  의도적 — 이동 알림은 "거짓 발화 < 미발화"지만 루틴은 "밋밋한 문구 > 미발화".
- 브리핑 줄은 `BriefingPayload.goal_lines`로 Core가 생성하되 **캐시에 저장하지 않고 반환 지점마다
  재계산**. 렌더러에서 그리려다 PanelApp/AvatarApp이 별도 React 트리라 스토어가 분리된다는 걸
  발견하고 선회했다.

**실사용 확인 후 추가** (`7f85c82`): 알림이 토스트로만 뜨고 채팅에 안 남아 지나가면 다시 볼 수
없었다. `messages`에 저장하도록 하면서 **`messages.source` 컬럼을 함께 신설**(0011) —
`null`(실제 대화) / `'briefing'` / `'routine_nudge'`. 나중에 컨텍스트 선별·RAG를 붙일 때
`WHERE source IS NULL`로 실제 대화만 고르기 위함이고, 태그 없이 쌓으면 그때까지 누적된 데이터를
되돌려 분리할 방법이 없어서다.

**DB 테스트 하네스** (`ba03d35`): 기존 테스트가 전부 순수 함수라 `&AppState`를 받는 함수는
검증 자체가 불가능했다. `core/src/testing.rs`의 `test_state()`(메모리 SQLite + 마이그레이션 +
AppState + 이벤트 수신기)로 목표 통합 테스트 17개 추가 — **89 passed**.
- ⚠️ 하네스는 **빈 비밀값 백엔드를 주입**한다. 안 하면 `SecretsStore::new()`가 Windows에서 실제
  OS 키체인을 읽어 `cargo test`가 진짜 OpenAI API를 호출한다.
- ⚠️ `sqlite::memory:`는 커넥션마다 별개 DB라 `max_connections(1)` 필수.
- 변이 주입(루틴에 DND 게이트 추가 / `user_id` 조건 제거)으로 해당 테스트 2개만 실패하는 것까지
  확인 — 빈 테스트가 아님을 검증.

**실사용 검증**: `npm run dev`로 알림 발화·채팅 반영 확인 완료.

**미해결 / 후속**
- **루틴 알림은 데스크톱 앱이 켜져 있어야 뜬다.** 밤 루틴이 이 한계에 가장 많이 걸린다.
  60분 지각 허용이 "잠깐 껐다 켬"은 덮지만 그 이상은 못 덮는다. 텔레그램 폴백은 보류.

  10시 영어"가 goal 아닌 반복 todo로 갈 위험이 있어, 경계를 프롬프트로 긋는 작업이 선행돼야 한다.
- `get_bool_setting` 사본이 4번째(notifications·schedule·travel·goals). 공용 헬퍼 추출은 별도 건.
- 하네스 남은 것: Whisper/TTS HTTP mock, LLM 응답 mock.
