# 작업 기록 — 2026-06-18

travel 기능을 사용자 정의대로 재조정 + 텔레그램에서 설정 가능하게.

## 1부 — 이동 동선 도구 재정의

기존 `list_today_travel`(오늘만, "일정들 사이" 프레이밍)이 원하는 정의와 어긋났음.
원하는 것: **지정 날짜의 일정을 집(또는 직전 일정 장소)에서 시작해 각 일정까지의
대중교통 수단·소요시간·출발시각 브리핑.** (거리는 요구에서 제외.)

- `list_today_travel` → **`plan_travel`**(read-only 도구)로 개명 + **`date` 파라미터** 추가
  (없으면 오늘, "내일"이면 현재+1). `services/travel/plan_travel_for_date(date)` 신설,
  `local_day_bounds_utc(day)` 일반화.
- 표시 지침 재작성: "〈출발 HH:MM〉 〈from〉 출발 → 〈to〉 (도착 …, 대중교통 N분, 환승 M회)",
  첫 구간 from이 집이면 "집에서 출발".
- 거리(distance)는 넣지 않음 — 시간·수단·출발시각만(기존 leg 필드 그대로).

## 2부 — 텔레그램 봇 설정 명령

데스크톱 설정 UI는 로컬 DB에만 써서 텔레그램(Fly DB)엔 집·별칭·토글을 넣을 수 없던 갭 해소.
텔레그램 명령은 ASCII만 허용되어 한글 대신 영문 명령:

- `/home <주소>` → `travel.home`
- `/leave on|off` → `notifications.leave_enabled`
- `/alias <별칭> <주소>` → `place_alias` 등록 / `/aliases` 목록
- 모두 Fly 코어의 `user_id=1`(공유)에 기록. 채팅 핸들러는 `/`로 시작하면 무시.

## 알게 된 것 (DB 분리)
데스크톱(로컬 SQLite)과 텔레그램(Fly 볼륨 SQLite)은 **분리된 DB**. 같은 `user_id=1`이라도
물리적으로 다름 → 데스크톱 설정이 텔레그램에 반영 안 됨. 통일은 remote 모드(공유 Core, D-013)가
정석이나 별도 작업. 당분간 텔레그램 설정은 위 봇 명령으로.

## 3부 — LangSmith(OTel) trace export (`feat/langsmith-trace`)

학습+디버깅용. chat agent loop을 LangSmith로 trace. **옵인 Cargo feature `langsmith`**로만
컴파일 → 기본/Fly 빌드엔 OTel 미포함(운영 비추적 = 프라이버시·빌드시간 보존).

- `infra/telemetry.rs`: OTLP/HTTP exporter(`api.smith.langchain.com/otel/v1/traces`,
  헤더 `x-api-key`·`Langsmith-Project`). `LANGSMITH_API_KEY` 있을 때만 활성, 없으면 no-op 스텁.
- trace 구조: 턴=`chain`(`agent_turn`), LLM 호출=`llm`(`chat_completion`, gen_ai.* + 토큰),
  도구=`tool`. parent-child 트리. Drop 시 부모 span 종료(여러 return 경로 무관).
- 실행: `npm run dev:trace`(= `build:core:trace` feature 빌드 + 앱 실행) + `LANGSMITH_API_KEY` env.
- **디버깅 삽질 기록**(다음에 또 안 헤매게):
  1. async reqwest exporter → 배치 스레드에 tokio reactor 없어 패닉 → **blocking client**로.
  2. blocking인데 export "network error" → opentelemetry-otlp가 끌어온 reqwest 0.13에
     rustls(aws-lc-rs)+native-tls 동시 활성 → 기본 rustls가 crypto provider 없이 실패.
     → `use_native_tls()` blocking 클라이언트를 `with_http_client`로 **직접 주입**해 우회.
  3. 엔드포인트는 `curl`로 `http=401` 확인(도달 정상) → 경로 아닌 TLS가 원인임을 특정.
- 검증: 데스크톱에서 "안녕"·"오늘 일정 알려줄래" → LangSmith에 trace 2건(tool span 포함) 확인.

후속(별개): orphan 대화 히스토리 새니타이저(chat.rs) — confirm 안 한 tool_call이 남으면
OpenAI 400. 지금은 `window.api.chatClear()`로 우회.

## 4부 — travel 실사용 디버깅/개선 (로컬 데스크톱 + LangSmith로 관측)

"오늘/내일 동선" 실제로 돌려보며 드러난 문제를 차례로 수정. 최종적으로 노선·환승역까지 실측 출력.

- **plan_travel 미호출 + 환각**: 모델이 도구를 안 부르고 이동시간을 지어냄 → 대화 히스토리에 남은
  이전 "API 안 됨" 턴 편향 때문. 대화 비우면 정상 호출. (LangSmith에 tool span이 없는 걸로 특정.)
- **Kakao 403 (OPEN_MAP_AND_LOCAL disabled)**: 콘솔에서 카카오맵(Local) 서비스 활성화(앱 단위).
- **도로명 주소가 키워드 검색 0건**: `/search/address` 폴백 추가 + "대한민국" 제거·콤마 분할
  후보 확장(`geocode_candidates`). Google 캘린더 장소가 "POI, 대한민국 전체주소" 꼴이라 통짜론 안 잡힘.
- **지저분한 라벨**("81, 대한민국 …"): `clean_label`로 첫 의미 조각만.
- **환승 구체화**: ODsay `subPath` 파싱 → `route_detail`(예: "4호선 혜화→동대문 / 2호선 …").
- **route_cache 구 포맷 잔존**: 캐시 키 mode `transit-v2`로 무효화(summary_json 의미 변경 반영).
- **present-hint 필드명 누출**(`depart_by`): placeholder→예시 기반 힌트로 교체.
- **관측성**: 지오코딩/경로 실패 + ODsay 에러 원문 로깅 추가.
- **채팅 복사**: 버블에 `select-text`(전역 user-select:none 위젯 드래그용을 버블만 해제).
- OTLP export 디버깅: blocking client + native-tls(rustls provider 충돌 우회) — 3부 참조.

로컬 주의: ODsay는 **집 공인 IP 등록** 필요(로컬 호출=집 IP, Fly egress와 별개). Kakao·ODsay 키는
데스크톱 키체인에 별도 입력.

후속: ① orphan 히스토리 새니타이저, ② plan_travel 미호출/환각 방지 system-prompt 보강
(이동 질문→도구 강제 + 추측 금지). 둘 다 별도 작업.
