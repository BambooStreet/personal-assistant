# 작업 기록 — 2026-08-14

## 자동 업데이트(auto-update) 도입 — Windows, 미서명(옵션 A)

**의도**: 한 번 설치하면 이후 새 버전을 자동으로 받아 적용되게 한다(그동안은 수동 재설치).
로드맵 보류 항목 "자동 업데이트 + 패키징"을 실제로 켰다. 브랜치 `feat/auto-update`.

**메커니즘**: `electron-updater`(NSIS) + GitHub Releases(public repo). electron-builder가
`build.publish`(github) 설정으로 `latest.yml` + 설치 `.exe`를 Releases에 올리고, 설치된 앱은
시작 시(또는 수동 확인) 새 버전을 백그라운드 다운로드 후 재시작하면 적용.

**핵심 판단**: 코어(`pa-core.exe`)는 설치본에 동봉하지 않음. 패키징 빌드는 remote(클라우드)
모드가 기본이라 로컬 코어를 안 띄운다(D-014) → 자동 업데이트 대상은 Electron 셸 + 렌더러뿐.
로드맵 1단계였던 `extraResources` 코어 동봉은 이번 범위에서 생략.

**변경 파일**:
- `package.json`(root) — `electron-updater` 의존성, `build.publish`(github: BambooStreet/personal-assistant)
- `apps/main/src/updater.ts` — 신규. `autoUpdater` 래퍼(초기 확인·수동 확인·quitAndInstall),
  진행 상태를 `update.status` 이벤트로 broadcast. dev(비패키지)에서는 no-op.
- `apps/main/src/index.ts` — whenReady에서 `initUpdater()` 호출(tray 생성 직후)
- IPC 3종(Main 자체 처리, Core forward 없음): `app.version` / `update.check` / `update.install`
  — `packages/ipc-types/src/methods.ts`, `apps/main/src/preload.ts`, `apps/main/src/ipc.ts`,
  `apps/renderer/src/lib/api.ts`
- `apps/main/src/tray.ts` — "업데이트 확인" 메뉴 항목
- `apps/renderer/src/components/settings/SettingsPage.tsx` — 일반 탭에 `UpdateSection`
  (현재 버전 표시·업데이트 확인·다운로드 진행률·"재시작하여 적용")
- `.github/workflows/release-desktop.yml` — 신규. `v*` 태그 푸시 → windows-latest에서
  `build:cloud` + `electron-builder --win --publish always`(GITHUB_TOKEN)
- 문서: `README.md`, `docs/planning/ROADMAP.md` 갱신(보류 → 구현 반영)

**검증**: `npm run build:types` 후 `npm run typecheck` 전 워크스페이스 통과. 로컬 설치본 빌드
(`npm run package:win`)와 실제 업데이트 왕복(태그 2개로 X.Y.Z → X.Y.(Z+1)) 테스트는 미실행 — 후속.

**남은/후속 작업**:
- 코드 서명(옵션 B, EV/Apple) — 미서명이라 첫 설치 시 SmartScreen 경고 1회. 사용자 베이스 안정화 후.
- 실기기에서 업데이트 왕복 테스트(quitAndInstall 시 before-quit 코어 셧다운 경로 확인).

## Google 로그인 수정 — Desktop 클라이언트 + client_secret 빌드 주입

**발단**: 방금 만든 미서명 설치본을 실행해 Google 로그인 시 `토큰 교환 실패(400): client_secret is missing`.

**원인 두 가지**:
1. 기존 OAuth 클라이언트가 **Web application 타입**이었음 → Google 토큰 엔드포인트가 client_secret 필수 요구.
   (코드/문서는 "Desktop app 타입, secret 불필요"를 전제했으나 실제 등록이 드리프트.)
2. Google **설치형(Desktop) 앱도 토큰 교환에 client_secret을 요구**한다("기밀 아님"이지 "불필요"가 아님).
   → 코드의 "secret 있으면만 전송" 전제가 잘못. secret을 반드시 넣어야 함.

**조치**:
- Google Console에서 **Desktop app** OAuth 클라이언트 신규 발급 → `BAKED.googleLoginClientId` 교체
  (`371336567345-mourr41...`). fly secret `GOOGLE_LOGIN_CLIENT_ID`도 같은 값으로 갱신(aud 검증 일치).
- client_secret은 **커밋하지 않고 빌드 시 주입**: `cloud.config.ts`에 placeholder(`__PA_CLIENT_SECRET__`)만
  두고, `scripts/inject-secret.mjs`(신규)가 `build:main` 뒤 env `PA_GOOGLE_LOGIN_CLIENT_SECRET`로 dist를 치환.
  - 로컬: `$env:PA_GOOGLE_LOGIN_CLIENT_SECRET` 설정 후 `npm run package:win`.
  - CI: GitHub 저장소 secret `PA_GOOGLE_LOGIN_CLIENT_SECRET` → `release-desktop.yml` 빌드 스텝에 주입.
- Desktop 클라이언트 secret은 배포물에 실려도 안전(Google 기준 비기밀 + 실제 접근제어는 클라우드
  `OWNER_EMAIL` 화이트리스트). Web 클라이언트였다면 불가.
- 문서: `DEPLOY.md` 9-1(“웹앱 타입 쓰지 말 것” 경고)·9-3(secret 빌드 주입 절차) 갱신.

**검증**: dev(remote) 로그인 성공, 로컬 설치본 로그인 성공. 주입 메커니즘 더미값 왕복 테스트 통과,
추적 파일에 secret 미유출(`apps/main/dist` gitignore).

**변경 파일**: `apps/main/src/config/cloud.config.ts`, `scripts/inject-secret.mjs`(신규),
`package.json`(build:main), `.github/workflows/release-desktop.yml`, `docs/guides/DEPLOY.md`.
