## 발단 — 새 개발기에 클론했더니 `npm run dev`가 안 떴다

노트북에서 하던 작업을 데스크톱으로 옮기려고 레포를 새로 클론했다. `npm install` 후
`npm run dev`를 돌리자 main이 컴파일 단계에서 죽었다.

```
src/core/remote-client.ts(2,33): error TS2307: Cannot find module '@pa/core-rpc'
src/core/supervisor.ts(3,54):    error TS2307: Cannot find module '@pa/core-rpc'
src/state.ts(1,33):              error TS2307: Cannot find module '@pa/core-rpc'
```

`packages/core-rpc/dist`가 없어서였다. 워크스페이스 패키지는 `package.json`의 `main`/`types`가
`dist/`를 가리키는데, `dist`는 빌드 산출물이라 gitignore 대상 — 클론에는 따라오지 않는다.

**그런데 그 `dist`를 만들어주는 사람이 없었다.** `dev` 체인은
`build:core → build:types → (renderer/main 동시 실행)`인데, `build:types`는 `@pa/ipc-types`만
빌드한다. `core-rpc`를 빌드하는 `build:core-rpc`는 `dev`에 없고, `npm install`도 워크스페이스
코드를 빌드하지는 않는다.

기존 개발기에서 안 터진 건 과거에 `npm run build`(= `build:core-rpc` 포함)를 한 번이라도
돌려서 `dist`가 남아 있었기 때문이다. CI도 `npm run build`만 돌지 `npm run dev`는 돌지 않아
그대로 지나갔다. **누구도 클린 클론을 밟아본 적이 없었던 셈.**

## `dev`만의 문제가 아니었다

`dist`를 지우고 `npm run typecheck`를 돌려보니 이것도 깨졌다. renderer가
`@pa/ipc-types`의 타입을 `lib/api.ts`에서 재export하는데, 원본 타입이 사라지자
`TS2459 declares 'CostSummary' locally, but it is not exported` 식으로 줄줄이 무너졌다.

프로젝트 기본 검증 명령이 클린 클론에서 못 도는 상태였다. `dev` 스크립트만 고쳤다면 이건
그대로 남았을 것이다 — 진입 명령마다 선행 빌드를 손으로 나열하는 구조 자체가 원인이라
빠뜨릴 자리가 계속 생긴다.

## 조치 — `prepare`로 진입점과 무관하게

- **`ipc-types` / `core-rpc`에 `prepare: tsc` 추가.** npm이 install 직후 워크스페이스
  패키지의 `prepare`를 실행해준다 → `npm install`만 하면 `dist`가 항상 준비된다.
  `dev`든 `typecheck`든 `dev:main`이든 무엇으로 시작하든 깨지지 않는다.
- **`dev` / `dev:main` / `dev:trace`의 `build:types` → `build:core-rpc` (보험).**
  `build:core-rpc`가 내부적으로 `build:types`를 부르므로 빠지는 것 없다.

검증: `dist` 두 개 삭제 → `npm install`만으로 재생성 확인, 그 상태에서
`npm run typecheck` 통과(종료코드 0). 삭제 직후 typecheck는 실패(2)로 재현도 확인했다.

Docker/CI 영향 없음 — `Dockerfile`은 `COPY . .` 뒤에 `npm ci`라 소스가 이미 있고,
`--omit=dev`가 없어 `typescript`도 설치된다. `NODE_ENV=production`은 런타임 스테이지에만
걸려 있다. `release-desktop.yml`도 `npm ci` → `npm run build:cloud`로 동일.
