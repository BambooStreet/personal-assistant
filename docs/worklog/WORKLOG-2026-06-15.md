## 핵심 설계 결정 (D-013)
- **단일 클라우드 두뇌**: 같은 `pa-core`를 Linux로 빌드해 Fly(도쿄)에서 구동. 텔레그램 봇·데스크톱이 클라이언트. 두뇌 복제 금지.
- **멀티테넌트 격리 = 공유 Core + 전 테이블 `user_id`**. DB 비어 있을 때 도입해 retrofit 비용 0.
- **쓰기 실행을 Core로 이관** → 클라이언트는 승인만(`approved`), 매핑 중복 소멸.
- **게이트웨이 = 공개 TLS + 강한 토큰**(v0). Tailscale 사설망은 후속 강화안.
- **폰 대화 = 데이터 공유 + 채팅 스레드 분리**: `user_id=1`로 todos·메모리·캘린더 공유, 채팅 로그만 `conversation_id="tg:<chatId>"`로 분리.

# 2부 — Google 로그인 인증 + 설치본 (같은 날 이어서)

env 토큰 수동 컷오버 대신 **"설치 → Google 로그인 → 클라우드 접속"** 진짜 유저 흐름 구현.
범위 A(단일 오너, 이메일 화이트리스트). 설계 = `docs/DECISIONS.md` **D-014**(인증), **D-015**(KST 타임존).
운영 절차 = `docs/guides/DEPLOY.md` 9절. 전부 `main` 머지·배포·**라이브 검증 완료**.

## 한 일
- **KST 타임존 버그 수정(D-015)**: 클라우드 컨테이너 TZ 미설정 → Local이 UTC → 시각 9시간 어긋남.
  `fly.toml TZ=Asia/Seoul` + Dockerfile `tzdata` + 다가오는 일정 표시 지침(`list_upcoming_events`).
- **클라우드 인증(cloud-bot)**: `/auth/google`(google-auth-library로 id_token 검증 + 오너 이메일
  화이트리스트 → jose HS256 **세션 JWT** 발급), 게이트웨이 WS를 세션 JWT 인증으로(레거시 토큰 병행).
- **데스크톱(main)**: 루프백 Google OAuth(`google-login.ts`, openid email+PKCE) → id_token →
  세션 발급 → `safeStorage` 암호화 저장. `auth.login/status/logout` IPC. 부팅 시 세션 있으면
  RemoteCore 접속·없으면 로그인 대기. 1008→재로그인.
- **렌더러**: `useAuthStore` + `LoginScreen`, auth→onboarding→앱 게이트. remote 모드는 온보딩 스킵
  (OpenAI 키는 플랫폼 시크릿이라 유저 입력 불필요).
- **패키징**: `cloud.config.ts`(packaged=remote 기본, client id 박음 — secret 미커밋),
  `build:cloud`/`package:win:dir`, pa-core 미번들.

## 라이브 검증 중 잡은 이슈
- Fly 공개 IP 미할당 → `fly ips allocate-v4/v6`(+ `flushdns`)로 게이트웨이 도달.
- 설치본 `Cannot find module 'ws'` → electron-builder가 루트 매니페스트로 추적 → 루트 deps에
  `ws`·`@pa/core-rpc` 추가.
- 부팅 직후 `core not connected` race → RemoteCore에 연결 대기 게이트.
- NSIS 인스톨러는 winCodeSign symlink 권한으로 실패 → `--dir`(win-unpacked)로 우회. 정식
  인스톨러는 개발자 모드 켜고 후속.

## 검증 결과
설치본(win-unpacked) 실행 → 자동 remote → Google 로그인 → 폰·데스크톱 **단일 두뇌**(한쪽에서
만든 할 일이 다른 쪽에 보임) 확인. 빨간 에러 없음.

## ⚠️ 남은 숙제 (다음에)
- **노출 비밀 재발급(미완·중요)**: 디버깅 중 OpenAI 키·Google client secret·refresh token이
  채팅에 노출됨 → OpenAI 키부터 revoke/재발급 → `fly secrets set` → `fly deploy`. Google은
  Cloud Console secret 재설정 → 데스크톱 재연결 → 재이식.
- **패키징 secret 주입**: cloud.config에서 secret 비웠으므로, 다음 `package:win` 설치본은
  로그인 토큰 교환 실패함 → 빌드 시점 secret 주입 방식 필요(현재 win-unpacked는 이미 박힌 채 동작).
- 정식 NSIS 인스톨러(개발자 모드), 범위 B(타인 가입·per-user Google·결제)는 SAAS-LAUNCH-PLAN.
