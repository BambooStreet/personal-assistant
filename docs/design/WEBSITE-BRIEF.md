## 1. 한 줄 요약

**MIYA** — 데스크톱에 상주하는 고양이 캐릭터 AI 비서. 일정·할 일을 대신 챙겨주고,
말을 걸면 대답하며, 아침에 오늘 하루를 브리핑해 준다. Windows 데스크톱 앱.

만들 것은 이 제품의 **소개 + 얼리액세스 신청 + 법적 고지**를 담당하는 웹사이트입니다.

## 2. 제품 개요 (카피 원천 자료)

### 무엇인가

화면 한켠에 200×200 크기의 고양이 아바타가 항상 떠 있습니다. 클릭하면 패널이 열려
채팅·할 일·설정을 쓸 수 있고, 호칭을 부르면 음성으로 대화할 수 있습니다.
브라우저 탭을 열거나 앱을 실행하는 동작 없이, **늘 거기 있는 비서**라는 것이 핵심 컨셉입니다.

### 현재 동작하는 기능 (전부 실제 구현·검증됨)

| 기능 | 내용 |
|---|---|
| **데스크톱 위젯** | 항상 위 표시(always-on-top) 아바타 + 별도 패널 창. 드래그 이동, 위치 기억, 투명 영역 클릭 통과 |
| **캐릭터·상태 표현** | 고양이 캐릭터가 5가지 상태(대기/주목/듣는 중/생각 중/말하는 중)로 바뀜 |
| **채팅** | 텍스트로 대화. 자연어로 일정 등록·할 일 관리까지 수행 |
| **음성 대화** | 호칭을 부르거나 단축키(`Ctrl+Shift+Space`)로 시작 → 자동 녹음 → 답변을 음성으로 재생 → 후속 질문 자동 대기(연속 대화) |
| **호칭 학습** | 사용자가 원하는 호칭을 직접 녹음해 학습시킴. 학습된 모델은 **PC 안에서만 동작** |
| **Google Calendar 연동** | 계정 연결 후 자동 동기화(30분 주기). "내일 3시에 치과" 같은 자연어로 일정 등록 |
| **할 일 관리** | 등록·완료·삭제. 기한순/우선순위 정리 |
| **아침 브리핑** | 그날 첫 실행 시 오늘 일정·할 일을 짧게 요약해서 말해줌 |
| **기억하기** | "이거 기억해줘" → 저장. 다음 대화에서 알아서 꺼내 씀 |
| **자동 업데이트** | 새 버전이 나오면 백그라운드 다운로드 후 재시작 시 적용 |
| **텔레그램 연동** | PC가 꺼져 있어도 휴대폰에서 같은 비서와 대화 (※ 현재 오너 계정 기준, 일반 공개 미정) |

### 차별점으로 내세울 수 있는 것

1. **API 키 입력이 필요 없다.** 사용자가 OpenAI 키를 발급받아 넣는 과정이 없습니다.
   AI 사용 비용은 운영자가 부담합니다. (경쟁 개인 프로젝트 대비 진입장벽이 확연히 낮음)
2. **브라우저 탭이 아니라 데스크톱에 산다.** 말 걸면 바로 대답하는 상주형.
3. **호칭 감지는 PC 안에서 처리된다.** 상시 녹음해서 서버로 올리는 구조가 아님 (9장 참조).

### 톤 & 무드

- 제품 성격: 귀엽고 친근한 고양이 비서. 딱딱한 B2B SaaS 톤 ✕
- 사이트 톤: **친근하되 과장 없음.** 1인 개발 프로젝트라는 사실을 숨기지 않는 편이 오히려 신뢰에 유리
- 언어: **한국어 단일.** 다국어(i18n) 대응은 이번 범위 밖

## 3. 사이트의 목표 (우선순위 순)

1. **Google OAuth 검증 요건 충족** — 앱이 Google Calendar 스코프(민감 정보)를 사용하므로,
   동의 화면에 등록할 **홈페이지 URL·개인정보처리방침 URL**이 실제로 존재해야 합니다.
   이게 없으면 앱 배포 자체가 막힙니다. **가장 급한 목적이며, 협상 불가한 요구사항입니다.**
2. **얼리액세스 신청 수집** — 지금은 아무나 설치해도 로그인이 안 되는 상태(5장 참조).
   따라서 메인 CTA는 "다운로드"가 아니라 **"얼리액세스 신청"**입니다.
3. **신뢰 확보** — 데스크톱 상주 + 마이크 + 캘린더 접근. "얘가 내 걸 다 훔쳐보는 거 아냐?"가
   1순위 의심입니다. 데이터 처리 방식을 정직하게 설명하는 페이지가 전환율을 좌우합니다.
4. **지원 부담 감소** — 1인 운영입니다. 설치 문제·자주 묻는 질문을 사이트가 대신 답해야 합니다.

### 성공 기준

- Google Cloud Console 동의 화면 심사에 제출 가능한 상태의 개인정보처리방침·이용약관 페이지가 산다
- 방문자가 "이게 뭘 해주는 앱인지" 스크롤 한 번(첫 화면) 안에 이해한다
- 얼리액세스 신청 폼이 동작하고, 신청 내역이 오너에게 도달한다

## 7. 페이지별 요구사항

### 7-1. `/` 랜딩

**첫 화면(above the fold)에 반드시**
- 제품명 MIYA + 한 줄 설명
- **움직이는 데모**(GIF 또는 무음 자동재생 루프 영상). 상주형 위젯은 글로 설명이 안 됩니다.
  이 자산 하나가 랜딩 전체의 성패를 가릅니다 (자산 제공은 15장)
- 주 CTA: **"얼리액세스 신청"**
- 부가 표기: `Windows 10/11 지원 · 현재 무료 · 초대 순차 승인`

**이후 섹션 (권장 순서)**
1. 핵심 기능 3~4개 — 2장 표에서 발췌. 기능 나열이 아니라 **장면**으로: "아침에 켜면 오늘 일정을 말해줍니다"
2. 음성 대화 시연 (오디오/영상)
3. **"API 키 없이 바로 쓸 수 있습니다"** — 차별점 강조 섹션
4. 데이터 처리 요약 3줄 + `/security` 링크
5. 제작자 소개 한 문단 + `/notes` 링크 (1인 프로젝트임을 정직하게)
6. 하단 CTA 반복

**금지**
- "완전 무료" 단정 (향후 유료 플랜 가능성 있음 → "현재 무료" 표기)
- 미구현 기능을 구현된 것처럼 서술 (2장 표에 없는 기능은 쓰지 말 것)

### 7-3. `/install` 설치 가이드

승인 통보를 받은 사람이 보는 페이지입니다. 다음을 **반드시** 포함:

1. 시스템 요구사항: Windows 10/11 (64비트)
2. 설치 파일 다운로드 링크 — GitHub Releases 최신본 (11장 사양)
3. **SmartScreen 경고 대응 안내** — 스크린샷과 함께 "추가 정보 → 실행" 클릭 경로.
   *왜* 뜨는지도 한 줄 설명(코드 서명 인증서 미적용). 감추지 말고 먼저 알려주는 편이 신뢰에 낫습니다
4. 설치 후 첫 실행: Google 로그인 → 승인된 계정이 아니면 로그인이 거부된다는 점 명시
5. 자동 업데이트 동작 방식 (새 버전 자동 수신 → 재시작 시 적용)
6. 제거 방법 (Windows 앱 목록에서 제거)

**9장 사실관계 시트를 그대로 근거로**, 일반 사용자가 읽을 수 있는 언어로 씁니다.

- 내 대화 내용은 어디에 저장되나?
- 마이크는 항상 켜져 있나? 내 소리를 계속 서버로 보내나?
- 캘린더에 어디까지 접근하나? 삭제도 하나?
- AI(OpenAI)에 뭐가 전달되나?
- 연결을 끊거나 데이터를 지우려면?

> ⚠️ **이 페이지의 문구는 9장 범위를 벗어나면 안 됩니다.** 예를 들어 "모든 데이터는 내 PC에만
> 저장됩니다" 는 **사실이 아닙니다**(9장 참조). 마케팅적으로 매력적이라도 임의로 쓰지 마세요.
> 표현을 바꾸고 싶으면 오너 확인 후 반영해 주세요.

## 8. 법적 페이지 요구사항 (Google OAuth 검증)

MIYA는 Google Calendar의 **민감 스코프**(`.../auth/calendar.events`)와 `openid`, `email`을
사용합니다. Google 심사 통과를 위해 개인정보처리방침 페이지는 다음 조건을 만족해야 합니다.

**형식 요건**
- 앱과 **동일한 도메인**에서 호스팅될 것 (OAuth 동의 화면에 등록할 홈페이지와 같은 도메인)
- 로그인 없이 **누구나 접근 가능**할 것, 안정적인 고정 URL일 것
- 사이트 어디서나 접근 가능할 것 (푸터 링크)
- 한국어 기준. 영문 병기 여부는 오너 판단

**내용 요건 — 다음이 명시적으로 들어가야 합니다**
1. 수집하는 정보의 항목 (9장 기준: Google 계정 이메일, 캘린더 일정, 대화 내용, 음성 녹음, 할 일·메모)
2. 각 항목의 수집·이용 목적
3. **제3자 제공/처리위탁** — OpenAI(AI 처리), Google(캘린더), 클라우드 호스팅 제공자
4. **국외 이전** — 데이터가 국외 서버에서 처리됨 (9장 참조). 한국 개인정보보호법상 고지 대상
5. 보유 기간 및 파기 절차
6. 이용자 권리 — 열람·삭제 요청 방법, 연결 해제 방법
7. **Google API Services User Data Policy 준수 및 Limited Use 요건 언급** — Google 심사에서 직접 확인하는 항목
8. 문의처(이메일) 및 시행일자

**이용약관에 들어갈 것**
- 서비스 제공 형태(현재 무료 얼리액세스, 사전 고지 후 변경·중단 가능)
- AI 응답의 정확성 미보증 — **일정 등록·삭제를 AI가 수행하므로 오작동 가능성 고지가 실질적으로 중요**
- 책임 제한, 금지 행위, 준거법·관할

> ⚠️ 법률 자문이 아닙니다. 개발자는 **초안 작성 및 페이지 구현**까지, 최종 문구 확정은 오너 책임입니다.

## 9. 사실관계 시트 (프라이버시·보안 문구의 유일한 근거)

**여기 적힌 것만 사실입니다. 여기 없는 내용은 쓰지 말고 오너에게 물어보세요.**

### 데이터가 실제로 어디 있나

- 현재 배포되는 설치본은 **클라우드 연결 모드**로 동작합니다. 대화·일정·할 일·메모는
  **운영자가 관리하는 클라우드 서버의 데이터베이스**에 저장됩니다.
- 서버 위치는 **일본 도쿄 리전**입니다 → 국외 이전 고지 대상.
- ❌ **"모든 데이터가 사용자 PC에만 저장된다"는 표현은 사실이 아닙니다.** 사용하지 마세요.
- PC에 저장되는 것: 로그인 세션 토큰(운영체제 암호화 저장), 창 위치 등 앱 설정,
  사용자가 학습시킨 **호칭 인식 모델**(브라우저 저장소, PC 밖으로 나가지 않음).

### 외부로 나가는 데이터

| 받는 곳 | 무엇이 | 왜 |
|---|---|---|
| OpenAI | 대화 텍스트, 음성 녹음(받아쓰기용), 답변 음성 합성 요청 | 대화 이해·응답·STT·TTS |
| Google | 캘린더 일정 읽기/쓰기, 계정 이메일(로그인 확인) | 일정 동기화·본인 확인 |
| 클라우드 호스팅(Fly.io) | 위 데이터 저장·처리 | 서버 운영 |

### 마이크 (가장 민감한 질문 — 정확히 쓸 것)

- 호칭(웨이크워드) 감지는 **PC 안에서 로컬 모델로 처리**됩니다. 상시 오디오를 서버로 스트리밍하지 않습니다.
- **호칭이 감지되거나 사용자가 단축키를 누른 뒤**의 발화만 받아쓰기를 위해 OpenAI로 전송됩니다.
- 상시 청취 기능은 **설정에서 끌 수 있고**, 기본값은 사용자가 켜야 동작합니다.
- 사용자가 직접 녹음한 호칭 학습 데이터와 학습된 모델은 **PC를 벗어나지 않습니다**.

### Google 접근 범위

- 요청 스코프: `calendar.events`(일정 읽기·생성·수정·삭제), `openid`, `email`
- **일정 생성·수정·삭제를 실제로 수행합니다.** "읽기 전용"이라고 쓰면 안 됩니다.
- Gmail·연락처·드라이브 등 다른 Google 데이터는 **접근하지 않습니다**.

### 비용

- 사용자는 API 키를 등록하지 않습니다. AI 사용 비용은 **운영자가 부담**합니다.
- 현재 이용료 없음. 향후 유료 플랜 도입 가능성 있음 → "현재 무료" 표기 권장.

### 보안 관련 사실

- 데스크톱 로그인은 Google 계정 로그인(OAuth) 기반이며, 별도 비밀번호를 만들지 않습니다.
- 세션 토큰은 운영체제 암호화 저장소에 보관합니다.
- 설치 파일에는 **코드 서명이 적용되어 있지 않습니다** (SmartScreen 경고 원인).
- ❌ "종단간 암호화", "제로 지식", "SOC2/ISO 인증" 같은 표현은 **전부 사실이 아닙니다**. 금지.
