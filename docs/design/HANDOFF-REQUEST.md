> 이 문서를 그대로 디자이너에게 전달하면 된다. 1차 핸드오프
> (`design/design_handoff_miya_personal_panel/`)를 받아 **토큰 층까지 코드에 반영한 뒤**,

## 1. 가장 중요한 것 — 우리 토큰 이름을 그대로 써 주세요

1차에는 shadcn 계열 이름(`--background`/`--card`/`--foreground`/`--primary`…) 39개가 왔고,
우리 시스템은 아래 이름을 씁니다. 옮기면서 **손으로 매핑표를 만들어야 했고, 여기서 사고가
날 뻔했습니다** — `--accent`가 양쪽에 있는데 의미가 반대였습니다.

> 원본 `--primary`(브론즈/골드) = 우리 `--accent`(주요 강조·버튼)
> 원본 `--accent`(버디그리) = 우리 `--teal`(보조 포인트)
>
> 이름만 보고 옮겼으면 주요 버튼이 전부 청록색이 됐을 겁니다.

**아래 이름으로 직접 주시면 매핑 단계가 통째로 사라집니다.** 값은 `"R G B"` 채널 3개
(공백 구분, `#` 없이) — `rgb(var(--토큰) / <불투명도>)` 형태로 쓰기 때문입니다.

| 토큰 | 용도 | 1차 원본에서 대응 |
|---|---|---|
| `--bg` | 앱 최하단·대화 영역 배경 | `--background` |
| `--bg-panel` | 카드·말풍선 등 표면 | `--card` |
| `--bg-elevated` | 활성 탭·보조 버튼·입력 배경 | `--muted` |
| `--fg` | 기본 텍스트 | `--foreground` |
| `--fg-muted` | 보조 텍스트 | `--muted-foreground` |
| **`--fg-subtle`** | **더 약한 텍스트·placeholder** | **원본에 없어 제가 지어냈습니다 — 값을 주세요** |
| `--accent` | **주요** 강조·기본 버튼 배경 | `--primary` |
| `--accent-fg` | accent 배경 위의 글자색 | `--primary-foreground` |
| `--line` | 테두리·구분선 (실선, 불투명) | `--border` |
| `--hairline` | 저불투명도 오버레이 채널(스크롤바 등) | 원본에 없음 — 값을 주세요 |
| `--sidebar` | 타이틀바 배경 | `--sidebar` |
| `--gold` / `--gold-soft` / `--halo` | 장식(이중 프레임·진행 바). 본문 텍스트에 쓰지 않음 | 동일 |
| `--sage` / `--rose` / `--teal` | 상태·분류 포인트 | 동일 (`--teal` = 원본 `--accent`) |
| `--accent-grad-from` / `--accent-grad-to` | 유저 말풍선·전송 버튼 그라디언트 두 스톱 | 원본은 단색 — 두 스톱을 주시거나 "그라디언트 폐기"라고 알려주세요 |

**자기 체계를 유지하고 싶으시면** 위 표의 오른쪽 칸을 채운 **매핑표만 같이 주셔도** 충분합니다.
제가 추측으로 짝지으면 조용히 어긋납니다.

### 라이트/다크 방향이 우리와 반대입니다

원본은 라이트 = `:root`, 다크 = `.dark`. **우리는 다크가 기본**이라 다크 = `:root`,
라이트 = `.light` 클래스입니다. 이 형식으로 주시면 그대로 붙습니다:

```css
:root {          /* 다크 (기본) */
  --bg: 23 19 14;
  ...
}
.light {         /* 라이트 */
  --bg: 246 245 242;
  ...
}
```

## 2. 물리적 제약 (여기서 벗어나면 다시 그려야 합니다)

- **패널 520×680 고정.** 1차는 660×960이었는데 실제로 띄워보니 위젯치고 너무 컸습니다.
  세로로 길고 내부 스크롤, 밀도 높게. 520 안에서 상단 탭이 몇 개까지 들어가는지도 같이
  봐 주세요 (현재 4개: 채팅·개인·비용·설정 / 1차 제안은 6개).
- **아바타 창 200×200, 완전 투명.** 아직 디자인이 없습니다. 배경·그림자·사각 프레임을
  두면 데스크톱 위에 사각 박스가 그대로 보입니다. 캐릭터와 상태 링만 그릴 수 있습니다.
- **12px 미만 폰트 금지.** 1차에 10.5~11.5px가 65곳 있었습니다. 예전에 10~11px로 갔다가
  가독성 문제로 전부 되돌린 이력이 있어 이건 지키고 있습니다. 폭이 520으로 줄면 더
  줄이고 싶어지실 텐데, 크기 대신 **색·자간·여백**으로 위계를 주세요.
- **패널 카드에 `border` 금지 → inset ring/box-shadow로.** 프레임리스 창이라 border 1px이
  레이아웃을 차지하면 상단 드래그 영역이 1px 밀려서 **창을 못 끄는 버그**가 됩니다.
  (1차의 안쪽 5px 골드 헤어라인은 `::before`로 옮겨서 잘 살렸습니다.)
- **등장 애니메이션 금지.** 불투명 창이라 `opacity: 0`에서 시작하면 검은 프레임이 한 장
  보입니다. 창은 콘텐츠와 함께 통째로 나타나야 합니다.

## 3. 폰트

- **제목·라벨 = 고운돋움(Gowun Dodum)** 으로 확정했습니다.
- ⚠️ **고운돋움은 weight가 400 하나뿐입니다.** 볼드가 없습니다. `font-weight: 600`을 주면
  브라우저가 가짜 볼드를 만드는데 라운드 산세리프에선 뭉개집니다.
  → **굵기 대비를 전제로 설계하지 말아 주세요.** 크기·자간·색으로 위계를 주셔야 합니다.
  (활성 탭도 굵기 대신 배경+색으로 구분하도록 바꿨습니다.)
- 본문은 산세리프 유지. 어떤 굵기를 쓸지 명시해 주세요.
- **웹폰트 CDN 링크는 못 씁니다.** 설치본이 `file://`로 뜨기 때문에 오프라인에서 폰트가
  통째로 사라집니다. 전부 번들하므로 **패밀리 수와 굵기를 최소로** 잡아 주세요
  (고운돋움 한글 서브셋 하나가 이미 400KB입니다).

## 4. 산출물 형식

1. **화면당 파일 하나.** 1차의 `.dc.html`도 좋았습니다. 다만 **인라인 스타일 대신
   Tailwind 유틸리티 클래스**로 써 주시면 그대로 복붙됩니다 — 우리 코드가 utility 전용이라
   인라인 스타일은 전부 손으로 번역해야 하고 그 과정에서 값이 미세하게 틀어집니다.
2. **색은 토큰 유틸리티로만**: `bg-bg`, `bg-bg-elevated`, `text-fg-muted`, `border-line`,
   `bg-accent`, `text-accent-fg`, `text-gold`… 하드코딩 hex 금지. (1차에서 이 원칙을
   지켜주신 덕분에 팔레트 교체가 값 치환만으로 끝났습니다.)
3. **상태 변형을 한 화면에 나열**: hover / focus / disabled / **빈 상태 / 에러 / 로딩**.
   뒤의 셋이 매번 누락되는데 실제 앱에선 자주 보이는 화면입니다.
4. **실제 데이터 길이로.** 긴 일정 제목, 5줄짜리 답변, 목록이 0건일 때 — 짧고 예쁜
   더미로만 그리면 520px에서 반드시 깨집니다.
5. 애니메이션은 duration·easing을 숫자로.

## 5. 스코프를 갈라 주세요 (이번에 제일 컸던 문제)

1차 번들에는 **리스타일과 신규 기능이 섞여** 있었습니다. 신규 기능 쪽은 DB 마이그레이션 +
프로세스 간 통신 계약 + 서버 로직이 함께 붙는 별개 작업이라, 한 번에 반영할 수 없습니다.

| 리스타일 (바로 적용 가능) | 신규 기능 (별도 작업) |
|---|---|
| 팔레트·타이포·간격·상태 | 개인 탭 → 일정/할 일/목표 3탭 분리 |
| 말풍선·카드·버튼·입력 룩 | 월간 캘린더 그리드 + 일정 CRUD |
| 이중 프레임·구분선·스크롤바 | 목표 마일스톤·로드맵·진행률 |
| 빈 상태·에러 표시 | 할 일 난이도·목표 연결 필드 |
| | 채팅 퀵 리플라이·메시지 액션·읽음 표시 |

**두 묶음을 다른 파일(또는 다른 문서)로** 주시면 앞쪽은 바로 반영하고 뒤쪽은 기능 설계와
함께 일정을 잡을 수 있습니다. 지금은 제가 손으로 갈라야 합니다.
